# 여행 가이드 설정 및 추천 운영 계획

작성일: 2026-09-01

## 1. 목적과 범위

`/travel-guide`는 고객이 여행 조건을 단계별로 입력하면 공개 카탈로그와 크루즈 추천 뷰를 기준으로 후보를 안내하는 화면이다. 이 화면은 예약 확정 또는 재고 확정 도구가 아니다. 가격, 좌석·객실 잔여, 픽업 가능 여부는 실제 예약 단계에서 플랫폼 원본으로 다시 확인한다.

현재 서비스는 크루즈, 호텔, 투어, 공항 이동, 차량의 5종이다. 고객에게는 조건에 맞는 후보와 확인이 필요한 운영 항목을 제시하고, 예약은 상품 상세 또는 예약 화면으로 이어진다.

## 2. 데이터와 설정 위치

| 구분 | 현재 데이터 원본 | 용도 | 운영 시 확인할 항목 |
| --- | --- | --- | --- |
| 크루즈 추천 | 플랫폼 동기화 공개 뷰 `public_cruise_recommendation_v2` | 객실 적합성, 요금, 선호 기반 점수 계산 | 일정, 객실 정원, 발코니·VIP·커넥팅·엑스트라베드 플래그, 유효 기간, 성인·아동·유아 요금 |
| 서비스 카탈로그 | 홈페이지 `catalog_products_v2` | 호텔·투어·공항·차량 상품 카드와 기본 정보 | `service_type`, 상품명, 설명, 카테고리, 대표 이미지, 활성 상태 |
| 서비스 가격 | 홈페이지 `catalog_prices_v2` | 날짜·최소/최대 인원 필터, 결과의 최저가 표시, 크루즈 예산 범위 | 통화, 금액, 단위, 최소/최대 인원, 적용 시작·종료일, 활성 상태 |
| 호텔 이미지 | 홈페이지 `hotel_gallery_images_v2` | 호텔 결과 카드 객실 이미지 | 상품 ID, 이미지 URL, 대표 여부, 정렬 순서 |

상품과 가격 데이터는 플랫폼 동기화 결과를 사용한다. 운영자는 가격을 바꾸기 전에 플랫폼 원본을 수정하고 홈페이지 동기화를 실행한 뒤, `/travel-guide`에서 반영 여부를 확인한다. 홈페이지 공개 카탈로그에 직접 예약·결제 원장을 만들지 않는다.

## 3. 공통 동작

1. 화면 로드 시 활성 상품·가격·호텔 이미지를 조회한다.
2. 고객이 서비스별 질문을 순서대로 선택한다.
3. 크루즈는 `/api/agent`의 `recommend` 모드가 전용 규칙 엔진을 실행한다.
4. 나머지 서비스는 브라우저에서 공개 카탈로그를 날짜와 인원 조건으로 필터링하고, 낮은 등록 요금 순으로 최대 12개를 표시한다.
5. 모든 결과는 참고용이다. 결과 카드와 안내 문구는 최종 요금·가용 여부를 현지 데스크 또는 예약 단계에서 확인해야 함을 표시한다.

## 4. 서비스별 현재 설정과 추천 근거

### 4.1 크루즈

고객 입력 순서는 여행 일정, 출발일, 성인·아동·유아 인원, 아동 나이, 객실 수·선호, 크루즈 예산, 여행 취향, 이동 필요 여부다. 당일 크루즈는 객실 질문을 건너뛴다.

추천 엔진은 다음 순서로 후보를 만든다.

1. 선택한 일정 코드 `DAY`, `1N2D`, `2N3D`와 출발일 유효 기간이 맞는 추천 뷰 행만 가져온다.
2. 객실 정원과 성인 정원이 `성인 + 아동 + 유아` 및 선택 객실 수를 충족하는지 확인한다.
3. 트리플, 커넥팅, 엑스트라베드, 싱글 객실 선호 조건을 충족하지 못하면 제외한다.
4. 적합한 객실 중 등록 성인 요금이 가장 낮은 객실을 각 크루즈의 대표 후보로 선택한다.
5. 기본 점수 45점에 추천 객실 플래그 8점, 가족·커플·발코니·시설·VIP 선호별 가점, 예산 적합 가점 또는 초과 감점을 적용한다.
6. `합리적인 가격` 선호는 성인 요금이 낮을수록 추가 가점을 적용한다.
7. 동점이면 등록 성인 요금이 낮은 크루즈를 우선하고 상위 3개를 보여 준다.

크루즈 예산 선택지는 활성 공개 VND 가격에서 동적으로 만든다. 선택한 성인 수와 객실 수를 곱한 참고 금액의 30%, 55%, 80%, 최대 구간을 제시한다. 추천 엔진도 다음 기준으로 예산을 비교한다.

$$
참고\,금액 = 등록\,성인\,요금 \times 성인\,수 \times \max(객실\,수, 1)
$$

아동·유아 요금, 엑스트라베드, 싱글룸, 유료 옵션, 프로모션·할증, 환율은 이 참고 금액에 포함되지 않을 수 있으므로 결과와 예약 단계에서 별도 확인한다.

#### 현재 크루즈 추천 데이터 기준

| 데이터 항목 | 추천 뷰 필드 | 현재 처리 방식 | 고객 화면에서의 의미 |
| --- | --- | --- | --- |
| 여행 일정 | `schedule_type`, `nights`, `itinerary_id` | 선택한 일정 코드와 같은 행만 후보로 사용 | 당일, 1박 2일, 2박 3일에 맞는 크루즈만 비교 |
| 출발 가능 기간 | `valid_from`, `valid_to` | 출발일이 있으면 기간 밖 요금을 제외 | 선택일에 적용 가능한 등록 요금만 비교 |
| 크루즈·객실 식별 | `cruise_id`, `cruise_name`, `slug`, `cabin_id`, `cabin_name` | 크루즈별로 적합한 객실 중 최저 성인 요금을 대표 후보로 선택 | 결과 카드의 크루즈명, 객실명, 상품 상세 링크 |
| 객실 수용 조건 | `max_adults`, `max_guests` | 성인·아동·유아 합계와 선택 객실 수를 충족하지 못하면 제외 | 일행이 실제로 머물 수 있는 객실만 추천 |
| 객실 구성 | `single_available`, `connecting_available`, `extra_bed_available`, `bed_type`, `room_area_text` | 싱글·커넥팅·엑스트라베드 선호는 필수 조건으로 처리. 트리플은 정원 3명 이상이 필수 | 원하는 객실 구조와 맞지 않는 후보 제외 |
| 관리자 추천 태그 | `tags`, `cruise_tags_v2.evidence`, `cruise_tags_v2.is_active` | 활성 태그가 고객 선호와 일치할 때만 가점하고 관리자 근거를 결과 이유로 표시 | 관리자가 직접 설정한 가족·커플·발코니·조용한 휴식·활동·가격·럭셔리 기준 |
| 운영 추천 여부 | `is_recommended` | 가점 8점 | 현지 운영 추천 객실을 우선 노출 |
| 가격 | `price_basis`, `currency`, `price_adult`, `price_child`, `price_infant`, `price_single`, `price_extra_bed` | 현재 성인 요금과 싱글 요금으로 대표 후보·예산 점수를 계산 | 결과의 등록 요금과 참고 예산 |
| 분류·설명 | `category`, `star_rating`, `description`, `tags`, `hero_image` | 현재 결과 카드에는 일부만 사용 | 후속 단계에서 테마, 등급, 분위기 설명에 사용 |

#### 현재 점수 기준

후보는 적합성 필터를 통과한 뒤 아래 점수로 순위를 정한다. 필수 조건을 충족하지 못한 객실은 점수가 높아도 후보가 되지 않는다.

| 기준 | 점수 | 적용 조건 |
| --- | ---: | --- |
| 기본 적합성 | 45 | 일정·출발일·정원·객실 구성 조건 통과 |
| 현지 추천 | +8 | `is_recommended = true` |
| 관리자 추천 태그 | +10~+13 | 관리자에서 활성화한 태그와 고객 선호가 일치. 저장된 근거 문구를 결과에 표시 |
| 예산 적합 | +20 | 참고 금액이 선택 예산 이내 |
| 예산 초과 | 최대 -20 | 초과 비율에 비례해 감점 |
| 합리적인 가격 | 0~+12 | 성인 등록 요금이 낮을수록 가점 |

#### 크루즈 고객 선택 세분화 계획

현재 입력 흐름에 아래 선택을 추가한다. 각 항목은 데이터가 준비된 뒤에만 노출하며, 아직 구조화되지 않은 항목은 상담 메모로만 저장하지 않고 먼저 표준 값과 필터 규칙을 확정한다.

| 단계 | 고객 선택 항목 | 연결할 데이터 | 추천 처리 | 우선순위 |
| --- | --- | --- | --- |
| 1 | 여행 목적 | `tags`, `category`, `description`에서 정규화한 `travel_theme` | 허니문, 가족, 휴양, 액티비티, 부모님 여행을 가점 또는 필수 조건으로 반영 | 높음 |
| 2 | 선호 객실 위치 | 신규 `deck_preference`, `view_type` | 저층/중층/고층, 오션뷰, 발코니 여부를 정렬에 반영 | 중간 |
| 3 | 식사·특별 요청 | 신규 `meal_options`, `dietary_support`, `special_amenities` | 제공 가능 상품만 표시하고 예약 단계에 전달 | 중간 |
| 4 | 승선 항구와 이동 | `itinerary_id`, 크루즈 위치, 셔틀·차량 가격 | 투안차우·하롱 국제선착장과 하노이·공항 이동 가능 여부를 검증 | 높음 |
| 5 | 객실 예산 방식 | `price_basis`, 각 연령·침대 요금 | 1인 기준, 객실 기준, 전체 예상 합계를 분리 표시 | 높음 |
| 6 | 출항 시간대 | 신규 `departure_time`, `return_time` | 이른 출발, 오후 출발, 하선 후 항공편 연결 가능 여부를 필터 | 중간 |
| 7 | 선상 활동 | `facilities`, `special_amenities`, 신규 `activity_tags` | 카약, 수영장, 쿠킹클래스, 스파 등 선호 활동을 가점 | 중간 |
| 8 | 등급·분위기 | `star_rating`, `category`, `tags` | 부티크, 럭셔리, 대형선, 조용한 일정 등으로 필터 또는 가점 | 낮음 |

#### 크루즈 세분화 구현 순서

1. 추천 뷰의 기존 필드로 가능한 가족·커플·발코니·VIP·시설 선택부터 화면에서 독립 선택 항목으로 분리한다.
2. 플랫폼 원본에 없는 항목은 크루즈별 표준 코드 목록과 입력 책임자를 정한 뒤, 공개 동기화 대상에 포함한다.
3. 새 선택값마다 `필수 제외`, `가점`, `상담 확인` 중 하나를 명시한다. 예를 들어 커넥팅룸은 필수 제외, 발코니는 가점, 식단 요청은 상담 확인으로 시작한다.
4. 가격 계산은 성인뿐 아니라 아동 나이, 유아, 객실 배치, 싱글·엑스트라베드, 유료 옵션, 프로모션·할증을 반영하는 플랫폼 공용 계산기로 교체한다.
5. 결과 카드에는 선택 항목별 추천 근거와 미확인 항목을 함께 표시한다. 예를 들어 `발코니 제공`, `4인 객실 가능`, `출발일 요금 적용`, `좌석 잔여 확인 필요`를 분리한다.
6. 변경 전후 동일 입력 조합의 후보 수·순위·참고 금액을 비교하고, 운영 담당자가 상위 결과를 검수한 뒤 점수 가중치를 조정한다.

### 4.2 호텔

입력은 투숙 예정일, 투숙 인원, 숙소 위치, 객실 선호다. 현재 후보 필터에는 날짜 유효 기간과 가격 행의 최소·최대 인원만 적용된다. 위치와 객실 선호는 화면에서 수집되지만 현재 데이터 계약에 대응 필드가 없어 결과 필터나 정렬에 사용하지 않는다.

운영 설정 시 호텔 상품은 `service_type = hotel`로 활성화하고, 가격 행에는 투숙 가능 기간과 수용 인원을 정확히 입력한다. 객실 사진은 `hotel_gallery_images_v2`에서 대표 이미지와 정렬 순서를 관리한다.

### 4.3 투어

입력은 투어 날짜, 참여 인원, 조인·단독·추천 후 결정 방식이다. 현재 날짜 유효 기간과 최소·최대 참여 인원만 필터에 사용한다. 투어 방식은 상담 참고값으로만 수집된다.

운영 설정 시 투어 가격 행에 최소·최대 인원과 유효 기간을 유지해야 한다. 조인/단독 구분을 자동 추천하려면 카탈로그 가격 또는 상품 메타데이터에 표준 `tour_style` 값을 추가한 뒤 필터에 연결한다.

### 4.4 공항 이동

입력은 픽업·샌딩·왕복 방향, 탑승 인원, 주간·야간·미정 시간대다. 현재 가격 행의 최소·최대 인원만 후보 필터에 사용한다. 방향과 시간대는 상담 참고값이다.

운영 설정 시 공항 이동 상품에는 공항 코드, 출발·도착 구간, 주간·야간 조건, 차량 정원, 수하물 정책을 구조화해 저장해야 한다. 이후 고객 선택값을 가격 행의 방향·시간대·정원 조건과 비교하도록 확장한다.

### 4.5 차량

입력은 하노이·공항·현지·직접 상담 구간, 탑승 인원, 편도·왕복·단독 대절 방식이다. 현재 가격 행의 최소·최대 인원만 후보 필터에 사용한다. 구간과 이용 방식은 상담 참고값이다.

운영 설정 시 차량 가격에는 실제 출발지·도착지, 편도/왕복, 차량 유형, 정원, 수하물 한도, 적용 기간을 분리해 등록한다. 크루즈 셔틀은 크루즈 예약 화면의 실제 요금 선택 로직과 별도로 운영되므로, 여행 가이드 결과를 예약 가능 여부로 해석하지 않는다.

## 5. 운영 점검 절차

1. 플랫폼 원본에서 상품 활성 상태, 가격, 유효 기간, 정원 정보를 먼저 갱신한다.
2. 홈페이지 카탈로그 동기화를 실행한다.
3. `/travel-guide`에서 서비스별로 날짜·인원을 바꿔 후보 수와 최저가를 확인한다.
4. 크루즈는 일정, 인원, 객실 선호, 예산, 선호를 각각 바꿔 상위 3개와 추천 이유가 달라지는지 확인한다.
5. 실제 예약 화면의 재검증 금액과 가이드의 참고 금액이 동일한 단위인지 확인한다. 가이드 금액이 정확한 결제 금액으로 보이지 않도록 안내 문구를 유지한다.
6. 상품 또는 가격이 없을 때에는 빈 결과와 상담 연결이 노출되는지 확인한다.

## 6. 우선 개선 계획

### 1단계. 데이터 정확도 개선

- 크루즈 예산 계산에 아동·유아 요금, 객실별 인원 배치, 싱글·엑스트라베드, 유료 옵션을 포함하는 공용 견적 계산기를 연결한다.
- 카탈로그 가격의 `price_unit`, 통화, 인원 범위를 전체 서비스에서 누락 없이 정규화한다.
- 출발일이 선택된 경우 크루즈 예산 범위도 해당 일정 코드의 요금만 사용하도록 일정 메타데이터를 명시한다.
- 크루즈의 여행 목적, 객실 위치·전망, 활동, 승선 항구·시간대를 표준 필드로 동기화하고 추천 필터와 점수 규칙을 연결한다.
- 관리자 추천 태그의 활성 여부와 근거 문구를 크루즈 추천 엔진에서 직접 사용하고, 비활성 태그는 추천 점수에서 제외한다.

### 2단계. 서비스별 실제 필터 연결

- 호텔의 위치·객실 선호를 상품 위치, 객실 타입, 조식, 수용 인원과 연결한다.
- 투어의 조인·단독 방식을 상품 또는 가격 메타데이터와 연결한다.
- 공항 이동의 방향·시간대를 실제 경로와 운행 시간 정책으로 필터링한다.
- 차량의 구간·편도/왕복을 `rentcar_price`의 경로와 이용 방식에 연결한다.

### 3단계. 설명 가능성과 운영 품질

- 결과 카드마다 제외된 주요 조건과 적용한 가격 행의 유효 기간을 표시한다.
- 추천 결과 로그에는 입력 조건, 후보 수, 제외 사유 분포만 기록하고 개인 식별 정보는 저장하지 않는다.
- 상품별 추천 성과와 상담 전환을 집계해 점수 가중치를 조정하되, 고객에게 과장된 확정 표현을 사용하지 않는다.

### 4단계. 예약 흐름 연결

- 결과 카드에서 조건을 예약 화면으로 안전하게 전달하되, 가격·재고·상품 상태는 예약 직전에 플랫폼 원본으로 재검증한다.
- 결제 금액은 여행 가이드의 참고 금액이 아니라 예약 생성 서버의 검증 결과만 사용한다.

## 7. 변경 시 검증 기준

- 크루즈 일정·출발일·인원·객실 선호를 바꾸면 부적합 객실은 추천에서 제외된다.
- 크루즈 예산 선택지는 활성 공개 가격이 있을 때 4개 가격 구간과 ‘제한 없음’을 표시한다.
- 예산 선택과 추천 결과의 참고 금액 계산식이 동일하다.
- 호텔·투어·공항·차량은 날짜와 최소·최대 인원 범위를 벗어난 가격 행을 결과에 사용하지 않는다.
- 가격 또는 상품 데이터가 비어 있어도 오류 대신 상담 안내가 표시된다.
- 데스크톱 1440px과 모바일 390px에서 금액은 오른쪽 정렬되고 가로 스크롤이 없어야 한다.
