# 홈페이지 점검 및 최적화 — 2026-09-18

## 결과

운영 사이트를 읽기 전용으로 점검하고 홈페이지 저장소에서 확인된 문제를 수정했다. 수정본의 프로덕션 빌드와 로컬 자동 검사 58건이 통과했다. 이번 변경은 Git 커밋까지이며 운영 배포는 포함하지 않는다.

## 검증 범위

- 기존 버전과 수정 버전 모두 `npm run build` 통과.
- 최종 전체 ESLint: 오류 0, 경고 5. 수정한 JS 및 검사 스크립트에 대한 별도 ESLint·구문 검사 통과.
- 기존 운영 `shthome.stayhalong.com`, `stayhalong.com`과 로컬 수정본을 비교.
- 수정본은 390px·1440px에서 36개 화면 검사를 통과: 두 도메인 홈, 크루즈·호텔 목록 및 각 대표 상세 1개, 예약 시작, 크루즈 예약, 공항 예약, 로그인, 회원가입, 비밀번호 찾기, 여행 안내, FAQ, 공지, 개인정보처리방침, 이용약관, 검색.
- 검사한 화면은 HTTP 200, 브라우저 실행 오류 0, 실패 리소스 요청 0, 깨진 이미지 0, 가로 넘침 0.
- 보호 경로 6개의 비로그인 로그인 리다이렉트 검증.
- 관리자·장바구니·문서 API 8개의 비로그인 접근 차단 검증. 이미지·관리자 문서 API는 지원하는 POST 메서드로 빈 본문을 보내 401 확인. 초기 GET 검사의 405는 접근 권한 문제가 아닌 검사 메서드 오류였으며 수정 후 재검사했다.
- 폐지 경로, 누락·잘못된 공개 API 입력, 비공개 이미지 경로 등 7개 응답 상태 검증.
- 예약 안내창 상호작용 검사 1건 통과. 합계 **58건 통과, 실패 0건**.
- 실제 운영 도메인을 로컬로 해석한 브라우저에서 공식 홈의 메뉴 7개와 임시 홈의 메뉴 미표시를 각각 확인. 공식 홈 콘텐츠·메뉴·CTA는 수정하지 않음.

## 남은 확인 사항

- 운영 배포 후 동일 검사 재실행이 필요하다. 현재 운영 사이트에는 기존 검색 링크와 이전 의존성이 남아 있을 수 있다.
- 실제 고객 로그인 후 예약 생성·변경·취소, 여권 업로드, 결제 및 관리자 저장은 실행하지 않았다. 이 결과는 예약·결제 전체 흐름이나 모든 고객 세션의 무결성을 보증하지 않는다.
- 전체 상품 상세를 전수 검사하지 않았으며 크루즈·호텔 대표 상세를 각각 검사했다. 운영 DB 정책·스키마·함수·트리거·기존 플랫폼 구현은 변경하지 않았다.
- ESLint 경고 5개는 관리자 원본/첨부 이미지의 `<img>` 2개와 기존 회원가입·상품 장바구니 이동의 `window.location.assign()` 3개다. 뒤의 3개는 새 Next.js 검사 규칙에서 추가로 탐지됐다. 인증·장바구니의 기존 이동 동작은 이번 점검에서 유지했다.
- 의존성 audit 0건은 패키지 공지 기준이며, 별도의 침투 테스트나 운영 DB 보안 진단을 대신하지 않는다.

## 재실행

프로덕션 빌드 후 별도 터미널에서 `node node_modules/next/dist/bin/next start --port 3100`을 실행한다. 이어서 PowerShell에서:

```powershell
$env:AUDIT_TEMPORARY_BASE = 'http://stayhalong.com:3100'
$env:AUDIT_HOST_RULES = 'MAP stayhalong.com 127.0.0.1'
$env:AUDIT_INTERACTIONS = '1'
$env:AUDIT_OUTPUT = '.migration-audit/homepage-final'
node scripts/homepage-audit.mjs http://localhost:3100
```

검사 스크립트는 실제 예약·결제·로그인 폼을 제출하지 않는다. JSON 결과와 화면 캡처는 Git 제외 경로 `.migration-audit/homepage-final/`에 저장된다. 운영 검사 시 `AUDIT_HOST_RULES`를 비우고 실제 두 도메인을 지정한다.
